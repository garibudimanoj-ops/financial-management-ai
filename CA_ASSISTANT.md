# CA Assistant — Feature Documentation

## What it can do
- Answer read-only questions about the active business (sales, invoices, payments, purchases, expenses, ledgers, reports).
- Explain basic GST concepts and how to use the app.
- Suggest drafts (invoice, expense, purchase) based on user prompts — marked clearly as unconfirmed drafts.

## What it cannot do
- Post, finalize, or commit any financial record without explicit user confirmation.
- Replace a qualified Chartered Accountant or provide legal/tax advice.
- Access data outside the active business/workspace.

## Safety and audit behavior
- Every interaction is logged (`audit_logs`) with `action: CA_ASSISTANT_INTERACTION`.
- Audit metadata includes `suggested_by: "ca_assistant"`, `action_type` (`read_query` or `action_suggestion`), message preview (first 200 chars), and `businessId`.
- Action suggestions create only draft records (`requires_confirmation: true`); the endpoint returns `requires_confirmation` so the UI can enforce confirmation before posting.
- All database queries are scoped to `context.businessId`; no raw SQL is generated by the LLM.
- Access is controlled by the `CA_ASSISTANT` permission (assigned to OWNER, ADMIN, STAFF roles by default).

## User-facing disclaimers
- The chat UI shows: "AI assistant — please review before relying on this for tax/legal decisions."
- Response messages include: "Not a replacement for a qualified CA."

## Example queries
- "What are my total sales this month?" → read query, no confirmation needed.
- "Suggest a draft invoice for Customer X with these items." → action suggestion; requires user confirmation before any record is finalized.

## Implementation notes
- Endpoint: `POST /api/ca-assistant/chat`
- Page: `/ca-assistant`
- Uses existing service layer for all numerical/financial operations; does not generate raw SQL.
- Preserves Decimal arithmetic and server-side RBAC.
